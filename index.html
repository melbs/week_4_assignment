Defining the ways to connect your CSS

I guess I have never realized when or why to use which approach, but hearing about technical writers and how they oftentimes do not have access to the external stylesheet, was an ah-ha moment. I made sure to write in my notes (and muscle memory):

  1. Link to a stylesheet file
  2. Add a <style> block in the <head> section
  3. Add style as an attribute on an element

1. Making sense of CSS

I was still a little confused with where to put a semicolon, colon, or space. I learned that you define a property and value separated by a colon :, and you always end the statement with a semicolon ; so the browser knows it's done.

2. Understanding "em" sizing

I never understood the .5 and 1 em thing before. I figured out that using 1em is just based on the size of the current font, and .5em is exactly half of that size. This makes it easier to scale spacing without guessing pixel sizes.

3. Acting as a Tech Writer

It really hit home connecting the tech writer POV of when to use what. Usually, you don't have access to the main stylesheet.css in a CMS. Because that is locked down, using "inline" options is the way to go. That was one of my biggest takeways as to why you would use one approach over the other. I love being able to put myself into the technical write role and decisons based off of that tech writer role.

For example: be sure the device has completely stopped moving before powering off. I used an inline style for this specifif verbiage so I can format it how I want it.
